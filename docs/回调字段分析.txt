# 📋 **项目现状总结与混合方案任务卡片**

## 🎯 **当前项目状况**

### **已完成的里程碑**
- ✅ 微信支付商户号已开通（`1738901706`）
- ✅ 微信支付V3 API已集成，可生成Native支付二维码
- ✅ 服务器SSL证书已配置，域名`lingyunai.cn`可访问
- ✅ 完整的支付控制面板（前端）
- ✅ 订单生成接口（`/api/payment/generate-link`）
- ✅ 回调接收接口（可接收完整回调数据）
- ✅ 密钥存储系统（`config/api_keys.json`）
- ✅ 基础项目目录结构已建立

### **待解决的问题**
- ❌ 微信回调数据**解密失败**（40小时未解决）
- ❌ 无法从回调体中提取准确的订单金额、时间
- ❌ 自动发货流程因缺乏验证数据而无法触发

### **决策方案：混合验证方案**
**放弃解密，采用“回调URL携带订单号 + 主动查询微信API”双重验证**

```
用户选择套餐 → 生成订单（包含唯一订单号）→ 生成支付二维码（回调URL嵌入订单号）→ 
用户扫码支付 → 微信回调（URL带订单号）→ 服务器记录回调信号 → 
服务器主动调用微信订单查询API（用订单号）→ 获取准确金额、状态 → 
验证通过 → 自动发放API密钥
```

### **卡片01：拆分微信支付配置**

### **卡片02：实现微信订单查询服务**
- **目标**：封装微信支付V3订单查询API
- **输入**：商户号、证书、APIv3密钥
- **操作**：
  1. 创建`services/wechat/query.js`
  2. 实现`queryOrder(outTradeNo)`函数
  3. 使用`GET /v3/pay/transactions/out-trade-no/{out_trade_no}?mchid={mchid}`
  4. 复用现有签名生成逻辑（`generateWechatPaySignature`）
  5. 处理成功响应，提取`trade_state`、`amount.total`、`success_time`、`transaction_id`
  6. 添加错误重试机制（失败后3秒、10秒重试）
- **输出**：可独立调用的订单查询模块
- **验证**：使用已支付订单号测试，能返回正确金额和状态
- **下一步**：卡片03

### **卡片03：重构订单生成接口（回调URL嵌入订单号）**

- **输入**：现有支付生成代码
- **操作**：

  2. 构建回调URL：`https://lingyunai.cn/api/wechatpay/callback/${outTradeNo}`
  3. 将订单号同时存储在`attach`字段（备用）
  4. 将订单信息存入`database/orders/`（JSON文件）
  5. 返回二维码信息及订单号
- **输出**：增强后的支付生成接口
- **验证**：生成的二维码回调URL包含订单号，订单文件正确保存
- **下一步**：卡片04

### **卡片04：创建订单管理服务**

- **下一步**：卡片05

### **卡片05：简化微信回调处理（仅记录信号）**
- **目标**：将原有复杂的回调解密替换为**只记录回调到达+提取订单号**
- **输入**：现有回调处理代码
- **操作**：
  1. 创建`services/wechat/callback.js`
  2. 实现路由`POST /api/wechatpay/callback/:orderNo`
  3. 从URL参数`orderNo`获取订单号
  4. 记录回调信息到`database/callbacks/`（时间戳、订单号、请求头）
  5. 返回微信要求的`{"code":"SUCCESS","message":"成功"}`
  6. **注意**：完全**不再尝试解密**请求体
- **输出**：干净的回调处理模块
- **验证**：收到回调时能记录订单号，文件正确保存，返回成功
- **下一步**：卡片06

---

### **卡片06：实现订单验证与自动发货触发器**
- **目标**：回调记录后，**主动触发**订单查询与验证流程
- **输入**：卡片02、卡片04、卡片05的输出
- **操作**：
  1. 在回调处理中，成功记录后**异步**调用`orderVerifier.verify(orderNo)`
  2. 创建`services/order/validator.js`
  3. 实现`verify(orderNo)`：
     - 调用`wechatQuery.queryOrder(orderNo)`获取微信订单状态
     - 若`trade_state !== 'SUCCESS'`，延迟重试（5秒、30秒）
     - 获取本地订单，比较`本地金额*100`与`微信金额`（允许±1分）
     - 若金额匹配，更新订单状态为`paid`，并触发`licenseDeliver.deliver(order)`
  4. 添加详细日志到`logs/queries.log`
- **输出**：完整的验证触发器
- **验证**：支付成功后，能在日志中看到验证成功并触发发货
- **下一步**：卡片07

1. **本地开发优先**：所有卡片在本地`E:\API-Service\`完成，每完成一张进行本地测试
